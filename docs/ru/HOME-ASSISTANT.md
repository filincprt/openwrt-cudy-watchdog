## Автоматизации, созданные через UI

- **«PassWall2 — событие от роутера»** — получает вебхук роутера, читает статус UCI и обновляет помощник статуса.
- **«PassWall2 — применение режима»** — преобразует выбранный режим-помощник в значение UCI и запускает оболочку.
- **«PassWall2 — обновление статуса»** — периодически считывает статус.
- **«PassWall2 — голосовые уведомления»** — сообщает об изменении статуса через Яндекс Станцию.

Пользователь предпочитает настройки через интерфейс HA и не редактирует вручную `configuration.yaml` или файлы сервера. Не предлагайте отдельную панель, если можно использовать существующий VPN-раздел.

## Метрики узлов PassWall2

OpenWrt публикует временные UCI-поля в `ha_watchdog_metrics.nodes`.

| Поле | Значение |
|---|---|
| `primary_ok`, `backup_ok` | `online` / `offline` по последней проверке |
| `primary_result`, `backup_result` | Результат HTTP (например, `204:0.353328`) или `no-response` |
| `primary_rtt_ms`, `backup_rtt_ms` | Округлённая задержка в миллисекундах или `unknown` |
| `primary_failures`, `backup_failures` | Число последовательных ошибок, ограниченное значением 3 |
| `primary_checked_at`, `backup_checked_at`, `last_check` | Локальные временные метки роутера |

Сводки отображаются в существующем разделе VPN через `input_text.passwall2_primary_metrics` и `input_text.passwall2_backup_metrics`. Автоматизация, созданная в UI, считывает `primary_summary` и `backup_summary` с помощью `openwrt.uci_get` раз в 30 секунд. Время в сводке — это время проверки на роутере, а не время обновления карточки.

## Частота публикации и нагрузка

Публикатор использует отложенные значения UCI и не делает commit метрик во flash при каждом обновлении. HA опрашивает уже опубликованную сводку каждые 30 секунд — сам по себе этот опрос не делает новую проверку узлов.

- В режиме `auto` обе проверки и решения о переключении продолжаются на каждом цикле; публикация метрик ограничивается случайным интервалом 180–300 секунд.
- В режимах `primary`, `backup`, `off` отдельная проверка метрик запускается каждые случайные 180–300 секунд.
- Значения метрик сбрасываются после перезагрузки до следующей публикации.

Фактическую периодичность ограничителя в режиме `auto` ещё нужно подтвердить по нескольким циклам: сравните `metrics_last_publish`, `metrics_interval`, `last_check` и системные логи. Сокращение частоты публикации не означает, что частота автоматических проверок тоже снизилась.
