# Снимок firewall и SSH (аудит только для чтения)

Сведения наблюдались на OpenWrt 25.12.6 2026-10-22. Это краткая сводка, а не полный экспорт правил.

## Зоны и политики по умолчанию

- Политики по умолчанию: `input='REJECT'`, `output='ACCEPT'`, `forward='REJECT'`.
- Зона LAN: сеть `lan`; входящий/исходящий трафик и forwarding — `ACCEPT`.
- Зона WAN: сети `wan`, `wan6`; входящий трафик — `REJECT`, исходящий — `ACCEPT`, forwarding — `REJECT`; masquerading включён, `mtu_fix='1'`.
- Перенаправление между зонами: `lan -> wan`.
- `fw4 print` завершился успешно. `nft list ruleset` показывал для inet fw4 политику drop по умолчанию на input/forward.
- В проверенном выводе не обнаружено пользовательских секций UCI перенаправления портов. Это не означает, что вышестоящий роутер полностью проверен.
- Наблюдались типовые правила DHCP/IPv6 ICMP, ping, IGMP/MLD и IPSec ESP/UDP 500. Не удаляйте их вслепую.

## Открытые слушающие порты

- Dropbear SSH, порт 22, слушал wildcard-адреса IPv4 и IPv6.
- uhttpd/LuCI слушал HTTP 80 и HTTPS 443 на wildcard-адресах; `redirect_https='0'`.
- DNS/dnsmasq привязан к LAN/WAN в рамках текущей конфигурации. У правил перехвата PassWall2 были активные счётчики.

Сам факт wildcard-привязки не доказывает доступность сервиса из WAN: важны firewall и настройки вышестоящего роутера.

## WAN и топология

- WAN IPv4: `192.168.1.164/24`, шлюз `192.168.1.1`.
- LAN роутера: `192.168.50.1`.
- Вероятен двойной NAT за вышестоящим роутером.
- Во время аудита WAN IPv6-адрес и IPv6-маршрут по умолчанию не наблюдались.
- В ходе этой проверки не обнаружили перенаправления портов или DMZ на вышестоящем роутере, но его настройки не исследовались исчерпывающе.

## SSH-ключ

- Отпечаток публичного ключа Windows, предоставленный пользователем: `SHA256:jDEprib9nD4I4w0cKSxMryYxlSR9sXCN1/0j4PchsjE`.
- Ключ был принят; журнал SSH явно сообщал `Authenticated ... using "publickey"`.
- Файл ключей роутера: `/etc/dropbear/authorized_keys`, владелец root и режим доступа 600. Файл `/root/.ssh/authorized_keys` также создавался и нормализовался.
- После проблем при переключении парольной авторизации пользователь восстановил доступ через LuCI. **Не считайте, что парольная авторизация сейчас выключена.** Перед настройкой проверьте `uci show dropbear`.
- Не отключайте вход по паролю, пока не подтвердили вход по ключу во второй независимой SSH-сессии. Во время изменения оставляйте текущую сессию открытой.

## Безопасные команды для повторного аудита

```sh
/etc/init.d/firewall status
fw4 print >/dev/null && echo 'fw4: OK'
uci show firewall
ubus call network.interface.wan status
ubus call network.interface.wan6 status
ip route show default
ip -6 route show default
uci show dropbear
```
